# Учебный Telegram-бот Макса

Бот на Python отвечает на сообщения:

- `/start` — «Привет, Макс, я твой бот.»
- `/help` — объяснение команд.
- `/price` — текущая цена одного BTC в USDT на спотовом рынке MEXC.
- `/change` — запрашивает сумму в рублях и рассчитывает необходимое количество BTC.
  Принимает, например, `100000`, `150 000`, `300 тысяч`, `100 тыс.` и суммы
  с копейками. Неверный ввод можно повторить; `/start` отменяет ввод суммы.
  Сумма временно хранится для пользователя до перезапуска бота.
- `/sergey` — «USDT для Сергея X»: запрашивает сумму рублей, автоматически получает
  курс USDT/RUB с Rapira и рассчитывает USDT по курсу с надбавкой 0,5%.
  `/start` отменяет диалог; выбор `/change` или `/sergey` начинает соответствующий расчёт заново.
- Обычный текст — «Ты написал: …» с повторением исходного сообщения.

В личном чате владельца команды доступны по кнопке «Меню» рядом с полем ввода.
При каждом запуске программа регистрирует `/start`, `/help`, `/price`, `/change` и `/sergey`
с русскими описаниями только для чата `ALLOWED_USER_ID` и включает в нём меню команд.
Публичные списки команд удаляются (общий, личные чаты, группы и администраторы,
без языка и для ru/en); глобальная кнопка сбрасывается на стандартную.
Для остальных аккаунтов серверный список команд пуст. Отображение кнопки и
обновление ранее сохранённого меню зависят от клиента Telegram: для обновления
может понадобиться закрыть и снова открыть чат. Доступ к самим командам
в любом случае разрешён только владельцу.
Если меню не обновилось сразу, закройте и снова откройте чат с ботом.

Длинный ответ разбивается на несколько сообщений в пределах лимита Telegram.
Неизвестные команды и нетекстовые сообщения игнорируются.

Команда `/price` при каждом вызове запрашивает последнюю цену сделки пары
`BTCUSDT` через публичный API MEXC:
`https://api.mexc.com/api/v3/ticker/price?symbol=BTCUSDT`.
API-ключ MEXC не нужен. Цена выводится с двумя знаками после точки.
В ответе указано время получения данных по Красноярску (UTC+7), а не время
сделки. Цена может измениться сразу после ответа. При недоступности MEXC
бот предлагает повторить команду позже, не подставляя старую или выдуманную цену.

Команда `/change` считает по формуле:

```text
Сумма с наценкой = рубли × 1,085
USDT = сумма с наценкой / курс RUB за 1 USDT (Binance)
BTC = USDT / цена BTC в USDT (MEXC)
```

Для USDT/RUB используется страница конвертера Binance:
`https://www.binance.com/ru/price/tether/RUB`.
Из JSON состояния страницы берутся цена именно USDT в USD и курс RUB за USD;
их произведение даёт курс USDT/RUB, используемый конвертером. Проверяются
выбранная валюта RUB, монета Tether USDT и режим конвертации. Это курс страницы,
а не предложение конкретного обменника или P2P. Запрос обходит старую кешированную
копию с помощью параметра времени и `Cache-Control: no-cache`. Страница Binance
публикует котировки с задержкой: при возрасте котировки больше пяти минут бот
добавляет её время по Красноярску (UTC+7) и уведомление о задержке.
Цена USDT должна быть положительной и не старше 15 минут. Более старые
данные, неизвестная структура страницы и другая валютная пара отклоняются.
Количество BTC вычисляется с точностью до восьми знаков и для вывода округляется
вверх до шести знаков; промежуточная сумма USDT перед расчётом BTC не округляется.
Ответ содержит исходную сумму, итоговое количество BTC и оба курса, например:

```text
Для суммы 100 000 руб необходимо 0.021700 btc (курс USDT: 100.0000 руб — Binance; курс BTC: 50 000.00 USDT — MEXC).
```

Курсы в примере условные. Наценка 8,5% включена в расчёт.
При недоступности одного из источников результат не выдаётся; можно отправить
сумму повторно или отменить ввод командой `/start`.

При временных сбоях бот сам делает до трёх попыток для каждого источника
с паузами 0,5 и 1 секунду. Повторяются сетевые ошибки, HTTP 408/425/429/5xx,
временно пустые или повреждённые ответы, а для Binance — также устаревшая
копия страницы. Каждый запрос Binance получает новый параметр времени,
включая повторы в одну секунду. HTTP 403 и ошибки валютной пары/структуры
данных завершаются ошибкой без повторов. Получение курса одного источника
ограничено 18 секундами; источники запрашиваются параллельно.

Если получить свежий курс всё же не удалось, ответ указывает конкретный источник:
Binance (USDT/RUB), MEXC (BTC/USDT) либо оба. В журнал записываются источник,
номер попытки, тип ошибки и HTTP-статус без секретов и содержимого ответа.
Перед расчётом возраст котировки Binance проверяется повторно, чтобы ожидание
второго источника не привело к использованию данных старше 15 минут.

## USDT для Сергея X — автоматический курс Rapira

Выберите в меню «USDT для Сергея X» или отправьте `/sergey`:

1. Введите сумму рублей, например `100000` или `100 тысяч`.
2. Бот сам запросит текущий курс Rapira и выдаст расчёт. Вводить курс не нужно.
3. В ответе указаны исходный курс Rapira и курс с надбавкой 0,5%.

Источник — публичный API `https://api.rapira.net/market/symbol-thumb`, который
использует сама страница `https://rapira.net/ru/exchange/USDT_RUB`.
Используется поле `close` пары `USDT/RUB`: последняя цена сделки, показанная
на странице как основной курс. Это не цена отдельной заявки на покупку/продажу.
Пара и валюты проверяются; запрос выполняется заново для каждой введённой суммы,
с параметром времени и `Cache-Control: no-cache`. API не сообщает время последней
сделки, поэтому бот не приписывает котировке неподтверждённое время обновления.

Формула:

```text
Курс для клиента = USDT/RUB Rapira × 1,005
USDT = сумма рублей / курс для клиента
Пример: 100 000 / (87,3 × 1,005) = 1 139,776489 USDT
```

Курс перед делением не округляется. Результат в USDT округляется вниз
до шести знаков после точки. Например, при курсе Rapira 87,3 руб:

```text
Для суммы 100 000 руб получается 1139.776489 USDT (курс Rapira: 87.3 руб; с 0,5%: 87.7365 руб).
```

Данные других бирж в этом расчёте не используются.

Временные ошибки Rapira автоматически повторяются по тем же правилам: до трёх
попыток за 18 секунд. При окончательном отказе бот предложит повторно отправить
сумму рублей; старый курс или другой источник не подставляется.

В облачной среде требуется HTTPS-доступ к `api.rapira.net`. Если прокси сообщает
`403 Domain forbidden` при уже сохранённом домене, проверьте разрешение сетевого
доступа текущей сессии через поддерживаемый запрос разрешений Codex.
18.10.2026 такой запрос восстановил доступ; разрешение выдано на текущий ход,
поэтому доступ после нового запуска среды нужно проверять заново.

## Установка

Нужны Python 3.10 или новее и доступ к PyPI для установки зависимостей.
В терминале Linux/macOS из папки репозитория выполните:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

В Windows активируйте среду командой `.venv\Scripts\Activate.ps1`
в PowerShell, затем выполните ту же команду установки через `python -m pip`.

## Проверка без настоящего токена

```bash
python -m unittest -v test_bot
```

Тесты проверяют ответы, регистрацию меню и обработчиков, фильтрацию команд,
длинные сообщения, чтение `BOT_TOKEN`, ввод рублей, расчёт, разбор страницы Binance
и ошибки источников, автоматический источник Rapira и диалог `/sergey`.
Ответы Telegram, MEXC, Binance и Rapira заменены заглушками; настоящий токен и доступ
к сети не нужны.

## Безопасное добавление токена

Получите токен своего бота у официального `@BotFather` в Telegram.
Бот читает его только из переменной окружения `BOT_TOKEN`.

В облачной среде добавьте значение в защищённое поле **секрета** `BOT_TOKEN`
в настройках среды, разрешив назначение `api.telegram.org`. Примените настройки
перед запуском. Если платформа использует прокси для секретов, для запуска
необходима совместимость этого прокси с Telegram Bot API.

Для локального запуска в Bash введите токен скрыто, без записи его значения
в команду и историю терминала:

```bash
read -r -s -p 'BOT_TOKEN: ' BOT_TOKEN
printf '\n'
export BOT_TOKEN
python bot.py
```

Не отправляйте токен в чат, не вставляйте в код и не коммитьте в Git.
`.env`, файлы ключей и типовые файлы секретов исключены через `.gitignore`.
Файл `.env` автоматически не загружается. Если токен стал доступен посторонним,
отзовите его через `@BotFather` и задайте новый в настройках секретов.

## Запуск и ручная проверка

### Доступ только владельцу

Бот отвечает только одному аккаунту, указанному в переменной окружения
`ALLOWED_USER_ID`, и только в личном чате. Узнать свой числовой Telegram ID
можно у `@userinfobot`. Это не имя пользователя и не токен.
Добавьте `ALLOWED_USER_ID` в переменные окружения облачной среды.
Локально перед запуском задайте `export ALLOWED_USER_ID=123456789`, заменив
пример своим ID. Значение не следует записывать в исходники.

Чужие команды и сообщения игнорируются без ответа и без получения курсов.
В группах бот молчит, даже если команду отправляет владелец. При отсутствии
корректного ID программа отказывается запускаться, чтобы не открывать доступ всем.

После установки зависимостей и задания `BOT_TOKEN` и `ALLOWED_USER_ID`:

```bash
python bot.py
```

Бот работает через polling; входящий порт и веб-сервер не нужны.
Требуется исходящий HTTPS-доступ к `api.telegram.org` и
`api.mexc.com`, `www.binance.com` и `api.rapira.net`. Запускайте только один
экземпляр для одного токена. При старте polling библиотека автоматически
отключает ранее установленный webhook.

Откройте своего бота в Telegram и проверьте `/start`, `/help` и сообщение
`Привет` — ожидаемый ответ на последнее: «Ты написал: Привет».
Затем отправьте `/price`: бот должен ответить ценой BTC/USDT на MEXC
и временем получения котировки.
Выберите `/change`, введите сумму в рублях и проверьте вывод расчёта с обоими курсами.
Выберите `/sergey`, введите сумму рублей: бот сам получит курс Rapira и выдаст USDT.
Для остановки нажмите `Ctrl+C`. Без `BOT_TOKEN` программа завершается
с понятным сообщением до обращения к Telegram.
