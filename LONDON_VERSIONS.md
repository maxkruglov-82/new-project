# Версии London

## V1 — сохранённая версия 39d55db

Файл: `KRYTES_V1_LONDON.txt`. Побайтная копия `KRYTES_OPEN_CLOSE_MASKED.txt` из коммита 39d55db, указанного пользователем. Заголовок в графике «V1 London». Этот файл не изменять при дальнейшей работе над V1.1.

V1 содержит HH/HL/LH/LL рядом с номерами без общей порядковой нумерации и прежний перенос 0 после неудачного закрепа. Часовой диапазон по теням, вход по двум касаниям RR1. Не следует приписывать этой сохранённой версии более позднюю фиксацию 0.

## V1.1 — текущая рабочая версия

Файл: `KRYTES_V1_1_LONDON.txt`. Заголовок в графике «V1.1 London». Совпадает с рабочими файлами `KRYTES_OPEN_CLOSE_MASKED.txt` и `KRYTES_OPEN_CLOSE_H1_BODY_RANGE.txt`; при изменении V1.1 обновлять все три копии одинаково.

Изменения после V1: первоначальная 0 неподвижна; общая порядковая нумерация структурных экстремумов внутри дня. Часовой диапазон остаётся по теням.

В V1.1 внедрены: замена неисполненного LONG со стопом за 1 на новый HL→HH после подтверждения HL и двух close выше прежнего HH; входы на ретесте после остановки на трёх M5 вместо двух касаний. Для LONG подтверждающее закрытие между стопом и RR1 и не ниже предыдущего close; SHORT зеркально. Вход по close, фактический RR не хуже 1:1. Структурное подтверждение high/low остаётся пять M5. V1 не меняется.

В последнем обновлении V1.1 буквенная рыночная структура строится непрерывно по подтверждённым пятисвечным поворотам тел M5 и чередуется high/low; она больше не ограничена опорами торгового сценария. Номера торговых точек и прежний шрифт сохранены. Данная визуальная разметка не изменяет условия сделок.

Дополнительно V1.1 возвращает неисполненный локальный LONG к основному стопу за точкой 1, если после ретеста без входа обновлён верхний HH; для входа требуется новый ретест пересчитанной зоны.

## Компактный файл для лимита KRYTES

`KRYTES_V1_1_LONDON_COMPACT.txt` — та же V1.1 без комментариев и пустых строк. Все инструкции, отступы, строки, шрифт и настройки сохранены. Генератор: `python indicator-tests/build-v11-compact.py`; при каждом изменении V1.1 компактный файл требуется пересобрать. На момент добавления полный файл 104 582 байта, компактный 91 097 байт. Сравнение всех выходных рядов PineTS на реальных MEXC 26 и 29 октября дало полное совпадение.

Оба файла меньше ограничения 200 КБ на скрипт. Если KRYTES пишет о превышении суммарных 600 КБ «Своих скриптов», необходимо удалить ненужные копии в самом терминале. Компактный файл уменьшает объём, но не гарантирует обход общего лимита при сохранении множества старых версий. При замене выделять весь старый код, не дописывать новый к нему. Сохранённые V1/V1.1 в GitHub от удаления копий в терминале не пропадают.

V1.1: отработка сценария без входа разрешает противоположную тройку структуры и ретест; все закрепы по одной M5; причина входа и RR отображаются в нижней части инструмента. V1 не изменялась. Компактный файл пересобран.
