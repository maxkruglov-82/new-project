Правила эксперимента:

- Точка 1: исходный свинг M5 и его перенос на новый экстремум принимаются только при закрытии соответствующей свечи строго за границей H1. Правое подтверждение свинга и прежний порог тени 0,02 сохранены. Для равного плато проверяется последняя свеча экстремума.
- Точка 3 в совместном варианте: появление и обновление P3 требуют подтверждённого закрытия строго за P1, включая разворотные исключения. Цена точки — high/low квалифицирующей свечи. Открытие свечи может оставаться внутри: за уровень должна выйти цена закрытия.
- Равенство уровня не считается закрытием за ним. Вариант только P1 сохраняет прежнее подтверждение P3 тенью.
- На свече нового экстремума вход по историческим OHLC не создаётся. Для совместного варианта отклонённая тень нового экстремума также исключает неоднозначный ретест на той же свече.
- Правила переключения приоритета, ведения открытой позиции, календаря, RR1:1 и отступыSL/TP0,03 сохранены. Отменённое изменение «после стопа сразу искать противоположную сторону» не добавлено. Первая точка, переиспользованная из P2 в существующем разворотном исключении, не является новым пробоем H1; правила её происхождения не менялись.

Винрейт = тейки / (тейки + стопы). Незавершённые и неопределённые исходы в знаменатель не входят. Числа таких входов доступны в Excel и полном JSON. 1R — фактический риск до стопа с учётом отступа; тейк меньше1R. Расходы не учтены. Экстремумы свечи входа не считаются последующими касаниями; одновременное касаниеSL/TP позже помечается неопределённым. Незавершённая позиция на новой опорнойH1 не получает фиктивного исхода.

Аудит PASS: непрерывность свечей, H1, формулы входа/SL/TP, независимое восстановление всех исходов, месячные суммы, совпадение августа–октября с предыдущим расчётом. В совместном варианте также проверена свеча P3 перед каждым входом.

По явной команде пользователя после сравнения публикуется только фильтр P1 как v36. P3 остаётся по правилам v35. Эксперимент P1+P3 не принят. Отдельные проекты NEAR и H4/M15 не изменялись.

Вывод для решения: совместный фильтр P1+P3 ухудшил винрейт и результат вR; оснований внедрять его по этому периоду нет. Только P1 поднял винрейт на0,55п.п., снизил результат на2,40R и максимальную просадку с8,33R до5,68R. Это компромисс между числом прибыльных сделок и просадкой, а не явное улучшение винрейта. После ознакомления с этим сравнением пользователь выбрал вариант только P1 и запросил публикацию; он принят как v36.

Всего входов / незавершённых: v35 —115/1; толькоP1 —104/3; P1+P3 —88/4. Неоднозначных исходов нет.

Публикуемый исходник отличается от рассчитанного P1-only черновика только названием indicator. Это проверяется тестом и change.json; повторный полный прогон из-за названия не выполняется. Журнал расчёта и исходный SHA256 сохранены, опубликованный SHA256 указан отдельно.

Повторить расчёт опубликованной v36: `node backtest/run_v36_halfyear.mjs` из new-project-2 с установленным PineTS0.12.0. Прогон проверяет весь журнал на сохранённых 52536 свечах и пишет reproduced-v36.json, не перезаписывая исходный расчёт.

Перед публикацией пройдено277 автоматических проверок, ошибок нет.
