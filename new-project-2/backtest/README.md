## Как воспроизвести

Из папки `new-project-2`, Python 3 и Node.js 22+:

```bash
npm install
python3 backtest/download_mexc.py \
  --start '2026-08-23T14:00:00+07:00' \
  --end '2026-10-22T15:00:00+07:00' \
  --output reports/mexc-sol-usdt-m5-2026-08-23_2026-10-22.json
npm run backtest -- \
  reports/mexc-sol-usdt-m5-2026-08-23_2026-10-22.json \
  reports/backtest-v27-60-days-2026-10-23
npm test
```

Для повторения на зафиксированных свечах пропусти скачивание: файл уже в
репозитории. Повторное скачивание меняет время получения и хеш файла;
биржа также может исправить свою историю. Отчёт сохраняет хеш данных
и самого индикатора, чтобы различать расчёты.

## Что именно считается

В обычных сценариях исключаются соседние центральные свечи P1/P2: сохраняется
P1, соседняя P2 пропускается. Между ними нужна хотя бы
одна свеча. Пока подходящей P2 нет, P1 сопровождает новый подтверждённый
экстремум. Старый [отчёт v7](../reports/backtest-v7-60-days-2026-10-22.md)
сохранён отдельно, поскольку раньше этот фильтр отсутствовал.

В v11 добавлен LONG после шортового диапазона без обновления первого low.
При пробое верхнего диапазона часа прежний шортовый low сохраняется как «0».
P2 нового LONG может пройти ниже H1, оставаясь не ниже «0». Верхнюю P1
сохраняем при соседнем нижнем свинге и ждём следующий более низкий low.
R:R подтверждён 1:1. [Отчёт v9](../reports/backtest-v9-60-days-2026-10-22.md)
сохранён отдельно; свечи для сравнения те же.

Исполняется сам `sol_short_setup.pine` в PineTS 0.12.0. `run.mjs` добавляет
только скрытые серии наблюдения за входом, исходом и публикацией H1;
условия стратегии, цены и присваивания состояния не заменяются.
Проверяется единственность мест вставки. При изменении исходника,
несовместимом с наблюдением, расчёт останавливается.

Визуальные настройки отключены для экономии памяти, на правила входа
и исхода они не влияют. Метки графика с ограниченным окном не используются
для подсчёта: читаются события всех 60 периодов. Дополнительный хвост,
требуемый движком для исторического режима, в отчёт не включается.

Период — 60 полностью завершённых циклов опорной H1. Первый час
14:00–15:00 23 августа, последний — 21 октября. Последний цикл заканчивается
в 15:00 22 октября по Красноярску. Это не 60 обязательных входов:
после стопа в том же цикле разрешены новые, после цели новые блокируются.

На M5 нельзя восстановить внутрисвечной порядок. Сохраняется поведение текущей версии:

- вход не приписывается историческому бару с новым экстремумом;
- проверка TP/SL начинается со следующей свечи после входа;
- если она содержит оба уровня, результат неизвестен;
- незавершённый вход при замене H1 учитывается отдельно, без выдуманной
  цены закрытия и без отнесения к победам или стопам.

Результат — касания уровней, а не исполнения реальных заявок. Стоимость
сделок, комиссии, финансирование и проскальзывание не включены. Винрейт
считается только по определённым исходам: цели / (цели + стопы).
`R` означает одинаковый риск на каждый вход; капитал и сложный процент
не моделируются. Неизвестные и незавершённые исходы не включены в сумму R.

Скачивание проверяет непрерывность, отсутствие конфликтующих дублей,
выхода за диапазон и допустимость OHLC; при пропусках нет частичного отчёта.
Дополнительно при первом запуске сверены все 60 H1, 87 цен входа и первые
последующие касания TP/SL непосредственно с сохранёнными свечами.

Тесты `tests/backtest.test.mjs` исполняют настоящий Pine на контролируемых
свечах: цель, стоп и новая противоположная попытка, неоднозначный исход,
незавершённый вход, TP на границе замены H1 и отказ при плохих данных.
Это отдельно от 173 проверок самого индикатора.

В облачной среде npm возвращал 403; фактические запуски использовали
официальные исходники того же PineTS v0.12.0 и временный загрузчик TypeScript,
описанный в [validation.md](../docs/validation.md). Код стратегии не подменялся.
